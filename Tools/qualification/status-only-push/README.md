# Private status-only native preparation

Not a shipping widget, Activity profile, bootstrap flow, consent factory or provider connection. No source here appears in the shipping package/project or widget bundle. There is no Activity request/update/end, native token operation, credential store, enrollment, HTTP transport or push registration.

The six fixture files are byte-preserved Core R6 private candidates. `activity-status-profile-tuple.json` defines the exact four-member canonical hash preimage. It is a proposal identity, not an accepted API profile. The human product choice permits status plus original observation time and retained old OS presentation; it does not supply genuine owner/native authority.

The new native type is `DJConnectRemotePlaybackStatusActivityAttributesV1`, separate from both the legacy local type and the earlier rich nine-field Tools prototype. It has exact two-field identity and an eight-field status ContentState. End requires explicit null playback state. All five client languages are represented; the candidate configuration reads the existing app-language helper. Minimal Island presentation is a neutral clock because no original timestamp context fits there. Background artwork is static brand-only drawing.

## Distinct validation boundaries

- Original producer/B-HTTP raw-byte preflight uses the existing strict Core lexical parser, then the candidate value decoder. The 33 frozen vectors test source-data shapes only, not authority or real OS/APNs rejection.
- Actual default Foundation decoding accepts integral decimal/exponent forms and collapses duplicate members. Tests preserve these counterexamples. ActivityKit supplies a Decoder, not a documented raw APS payload hook. Native value/keyset/identity/null checks do not claim to replace original Core/API raw preflight.
- The stateless renderer neither enforces cross-update sequence order nor derives a local validity lease. Original timestamp formatting uses no arrival/current time or expiry. Genuine bootstrap, target proof, signed environment, storage/locked display, revoke/error schemas, same-second APS ordering and provider/native acceptance remain separate open gates.
