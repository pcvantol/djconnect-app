# Apple consolidation — 23 October 2026

The resumed Apple candidate retains the original PR183 work and adds:

- Current Track Insight rejects an expired original short monotonic lease before
  applying content, history, widgets or Activity state. Deterministic AppModel
  controls cover a one-second lease, strict equality, a slow read with a lagging
  wall clock, and a valid read. A private counterfactual restoring the missing
  guards fails the same actual AppModel tests; the fixed source passes.
- Session suggestions remain eligible after first playback; Session Help selects
  the Session surface. The server catalogue remains authoritative. Its current
  draft pin is unqualified, so it grants no executable examples or padded chips.
- The separate native surface registration primitive retains original owner,
  Session, purpose, token, wall and monotonic witnesses. It scrubs local read
  credentials before rotation or withdrawal, refuses uncertain replay, preserves
  Core's same-generation revision+1 contract and rejects unsafe revisions.
- Background projection v2 is a separate decoder. Foreground v1 admission stays
  unchanged. Its original observation/expiry and explicit per-field status and
  passive rights are preserved; no artwork route or ordinary bearer is exported.
- Exact Core12675bc source fixtures are retained alongside the older fixtures:
  Bulletin `1f6ae4e`, current subject `2164c091`, surface HTTP `ec2ff503`.
  These are isolated producer tests with explicit synthetic boundaries.

The push source is preparation, not an operational delivery claim. Normal Core
purposes remain empty until actual issuer enrollment/service adoption. The new
background decoder and registration primitive do not automatically authorize
or activate a background client. Actual native target/environment qualification,
first-read owner-bound pinning and extension transport remain separate work.
Live Activity rich transport needs its own admitted schema and rights: the
existing local monotonic receipt must never be supplied by a server. A neutral
Activity codec test does not implement rich playback push.

Consolidation, protected merge, one new ordinary build and installation on the
owner's devices were explicitly requested. Source checks, signed artifacts,
installation readback and actual push/visual/audio acceptance must be reported
separately. No VibeCast runtime or physical-TV acceptance follows from compilation.
