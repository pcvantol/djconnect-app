# Automatic paired device discovery: first client increment

The client adopts the passive role-state subset of Core protected source `e84ffd25a37f97bf79d0806a30ff0fe9d14d6695`, contract `docs/product/AUTOMATIC_PAIRED_SURFACE_REGISTRATION_V1.json` SHA256 `af201f6a74f358b09460f3cea026b6104aef93d54d8ac9ea05bac32d43874492`. The contract records the producer routes and acknowledged purpose-epoch producer as not implemented. No successful server registration is inferred from this client source.

After a genuine authenticated status response, the foreground paired app queries the exact device role-state paths using its ordinary current device credential and already-loaded HA installation ID. Device discovery has no active Session or Profile requirement. iPad physical platform remains `ipados` while its ordinary client type is `ios`. Mac queries its widget role; iPhone/iPad query their independent widget and status-Activity roles. Watch native roles remain unavailable. There is no additional owner-approval UI.

The new family has a separate bounded no-store GET transport, closed role paths, strict canonical bytes/key order/types, original coordinate data and exact local device/platform/application/installation comparisons. It strips ambient credentials/cookies/headers, rejects redirects, never falls back or retries a write and rejects response/status contradictions. Auth-generation is opaque text. An AUTHORITY_CURRENT descriptor is comparison data, not a verified original A receipt, clock witness, SDK capability or display grant.

In-memory query ownership has an independent runtime epoch and pairing-attempt identity. Unpair/background/changed owner clears data and cancels pending reads. Late nil-return ABA or credential-loss replies cannot repopulate a later owner. Query throttling is only local read pacing, never a grant lifetime. Missing route, unavailable server or auth failure cannot reset ordinary pairing or arm the existing native task owner.

This increment does not yet consume child indexes/B receipts, verify a Core signature, reserve a native operation, acquire WidgetKit/ActivityKit tokens, create/migrate an Activity or submit a provider request. Existing Session-bound surface and native-registration families remain unchanged. Complete child/target lifecycle, actual native protocol/key-mode/role/reservation/clock/provider qualification, shipping status-only display adoption and real delivery remain open.
