That is an accepted design and working implementation, not a protected operative server pin.

The immutable pre-context attempt captures the original native request, operation UUID, installation, device/client, target, token digest and runtime owner epoch. Context and registration use that same operation. The paired context response must have exactly the nine v2 fields. The registration request changes only contract_version and context_handle; no continuation field is forwarded to API. The v2 Core ACK must echo the original handle, operation and purpose reference and use the closed confirmed/unconfirmed variant. A failed response cannot contain a background credential. Existing registration lifecycle still checks receipt coordinates, revision, role and confirmed phase.

The original grant expiry remains distinct from the short context submit window. Monotonic is sampled before wall time. Context requests and registration dispatch are fenced before URLSession resume and after return; a local thirty-second budget can shorten, never extend, the server window. An expired original attempt makes zero HTTP calls. The server purpose reference establishes an original RAM pin; native token rotation must retain that exact pin and original expiry across later operations and wall rollback. Changed installation, owner, device, client, target, platform, purpose reference or expiry cannot substitute a successor for the original grant. The context deadline is not a registration/read lease.
