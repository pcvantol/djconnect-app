## Presentation and arbitration

One RAM-only operation owns the expanded card. Core inventory provides stable ordering, concrete original subjects, availability and localized labels/copy. Opening/scrolling/closing is read-only and cannot research or prefetch. Only one selected original type begins work. Pending/result takes local foreground priority over proactive/reaction presentation; genuinely accepted other Moments stay in server history.

The existing current/result renderer uses Core's exact owner-only explicit presentation admission while paused or after a track change. It does not substitute the newly playing subject. Immediate server retention and original entry-ID are accepted facts from the producer; non-retained mode stays explicit. Closing a committed result changes placement only. Cancel before acceptance uses the original operation; cancel after commit cannot claim history deletion. Restoring/reconnecting reads original history without regenerating, autoplay or an old presentation window.

## Visible budget and accessibility

`AskDJMomentsPresentation` is a local presentation reducer, not an authority or retention store. Its twenty seconds count only actually visible, unheld foreground time, keyed to the original generation/Moment-ID. Network arrival and Core creation time never start this budget. Native scroll visibility plus window/scene visibility gates rendering; merely mounting a minimized Mac view is insufficient. Reading/expanded text, photo viewer, actual speech for that exact Moment and accessibility interaction hold the budget. Actual preparation for that exact speech reference has a separate processing hold, set synchronously by the existing speech owner; it is never reported as speaking. An unrelated speech reference cannot hold this result. Dismissal/withdrawal prevents all late callbacks from reopening it. Core/source/media expiry always wins over a local hold; neither status polls nor timer activity renews rights.

Dynamic Type uses an internally scrollable chooser and flexible rows, with a broad-layout adaptive grid rather than truncating the inventory. Controls have explicit semantic keyboard/VoiceOver actions and preserve focus. Existing Reduce Motion/Transparency and Mood glass/Avatar identity remain the presentation owners. Core type/reason label maps follow the client interface language. Original subject, pending and story copy keep Core’s original locale. Five-language interface copy and actual Core content locale are checked independently.

## Original operation, history and speech

The original request task and read-only status task are independent. A status click cannot cancel a still-running POST. Lost cancel delivery retains the original operation-ID and an honestly unconfirmed cancellation; a later committed result wins. Once accepted, late pending/error callbacks cannot replace the contribution. A bounded read-only accepted-status observer can process an explicit `accepted_result_unavailable`; it cannot restart the visible window, autoplay or extend the fixed grant.

Core commits the original Moment/entry before acceptance.
